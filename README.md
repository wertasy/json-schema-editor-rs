# jse — JSON Schema TUI 配置编辑器

`jse` 读取一份 JSON Schema，生成 menuconfig 式的终端配置界面（单屏滚动列表：面包屑 + 条目 + 帮助栏），光标移动、就地编辑、层级钻取、当前路径向下搜索（标题/键/值），编辑即时写回；保存前用 [jsonschema](https://github.com/santhosh-tekuri/jsonschema) 库做权威校验。

## 安装

预编译二进制见 [Releases](https://github.com/wertasy/json-schema-editor-rs/releases)：Linux / macOS / Windows，amd64 与 arm64；压缩包内含 `jse`、`README.md`、`LICENSE`，`checksums.txt` 提供 SHA-256 校验和。

源码构建：`cargo build --release`（Linux / macOS / Windows；Linux 静态发布目标为 `x86_64-unknown-linux-musl`）。`jse --version` 输出发布版本、提交与构建时间。

`cargo install --path .` 安装本地构建；版本号取自 crate 版本与构建元数据，`jse --version` 显示 `jse vX.Y.Z`（没有提交/构建时间时省略括号部分）。

## 用法

```
jse [-s <schema路径|http(s)://URL>] [-p|--pick] [-f|--force]
    [-a|--accessible] [-v|--version] [-h|--help] <config.(json|jsonc|yaml|yml)>...
```

示例：

```sh
# 编辑已有配置（原地写回）；文件不存在则从空文档开始、保存时创建
jse -s examples/server.schema.json server.json

# schema 地址写在配置顶层的 "$schema" 键里（无需 -s）
jse server.json

# 使用远端 schema
jse -s https://example.com/schemas/server.schema.json server.json

# 版本、帮助、行式（无 TUI）模式
jse -v
jse -h
jse -a -s examples/server.schema.json server.json
```

## 配置格式

按扩展名选择读写格式（大小写不敏感）；未知扩展名或无扩展名按 JSONC 处理，保持历史上「一律 JSON」的行为：

| 扩展名 | 格式 | 说明 |
|---|---|---|
| `.json` / `.jsonc` | JSONC | 严格 JSON 的超集：`//` 行注释、`/* … */` 块注释、对象/数组尾随逗号；其余文法与 `encoding/json` 一致 |
| `.yaml` / `.yml` | YAML | 锚点/别名保留：别名引用不展开，菜单顶部 `< Expand >` 物化为副本；合并键 `<<: *a` / `<<: [*a, *b]` 保留并在菜单中合并展示（见「界面与键位」；状态栏提示保留的引用数）；多文档、非字符串键、`.inf`/`.nan` 报错退出 |

- **注释保留**：注释跟随所属键/值，编辑该成员后仍在；删除成员时其注释一并消失；新增成员没有注释。JSONC 中与值同行、写在逗号后的注释归该值；下一行注释归下一个键。空行不保证保留（YAML 发射器会归一化）。
- **schema 指向**：`-s` 或 SchemaStore 选择的结果按格式记录——JSON/JSONC 用顶层 `$schema` 键；YAML 只用文件头 `# yaml-language-server: $schema=<位置>` 注释，不添加也不填充 YAML 里的 `$schema` 键。两种写法都会被后续启动识别。
- **无注释 JSON 零回归**：`.json` 没有注释时保存输出与旧版完全一致（委托给 `jsondoc.Node.Write`）。带注释/尾随逗号的旧 JSON 现在可以正常打开。
- YAML 时间戳按字符串编辑，保存后写回原文本；`!!binary` 与未知标签按普通字符串处理（保存后不再带标签）。数值字面量归一化为 JSON 数字（`0x1F` → `31`、`1_000` → `1000`），`1.0`、`1e3` 这类合法 JSON 字面量保持原样。
- 内置 raw 编辑器与 `$EDITOR` 外部编辑器使用**文件自身格式**：JSON/JSONC 文件用 JSON 文本，YAML 文件用 YAML 文本；整份文档、无法表单化的字段、需要用外部编辑器打开的 schema 未定义值（无值或对象/数组）均一致。保存时仍按文件原格式写回。
- 新增格式只需实现一个只依赖 `src/doc/jsondoc` 的转换模块（`Codec` 实现），并在 `src/doc/mod.rs` 的 `FORMATS` 注册（接口见该模块注释）。

## Schema 来源（按顺序解析）

1. 显式 `-s`：`http://`/`https://` 开头 → 远端抓取；否则视为本地路径。
2. 无 `-s` → 读配置自带的 schema 指向：JSON/JSONC 为顶层 `$schema` 字符串；YAML 还可读文件头的 `# yaml-language-server: $schema=…` 注释（显式 `$schema` 键仍优先）。URL 直接用；无 scheme 的相对路径先相对**配置文件所在目录**解析，该目录下不存在时回退到**当前工作目录**。
3. 两者皆无 → 查 SchemaStore 公共目录（schemastore.org）：按文件名做 `fileMatch` 匹配，**唯一命中直接采用**；歧义或未命中都打开检索选择器（`--pick` 强制打开）。选中即用，中止 → 报错 `no schema found: …`，exit 2。
4. 目录里也没有 → 报错 `no schema found: provide -s or record the schema location in the config`，exit 2。

选择器（TUI 全屏：输入过滤、↑/↓ 或 `ctrl+j`/`ctrl+k` 移动（`tab`/`shift+tab` 等同下/上方向键）、enter 选定、esc 取消；`--accessible` 为行协议：输入搜索词 → 编号列表 → 数字选择，`0` 重搜、空行中止）。自动匹配或选定的 URL 按 `-s` 同样规则写回配置的 schema 指向（JSON/JSONC 顶层 `$schema`；YAML 文件头注释），下次启动直接走第 2 优先级；`--pick` 则强制重选并覆盖既有指向。

schema 抓取失败（路径不存在 / HTTP 非 2xx / 超时）→ exit 1（远端 schema 有可用缓存时改为回退到缓存，见下节）。远端 `$ref`（包括相对 base URI、`$id`）同样支持；不可达的 ref 降级为原始格式编辑（JSON 或 YAML，见下文）。

## 远端 schema 缓存

远端 schema（`http(s)://`）首次抓取后缓存到本地，之后的启动不再重复下载：

- **位置**：`$XDG_CACHE_HOME/jse`（通常是 `~/.cache/jse`），可用环境变量 `JSE_CACHE_DIR` 覆盖（例如 `/tmp/jse`）；目录不可写时静默降级为不缓存（不影响功能）。
- **有效期 24 小时**（`src/fetch.rs` 的 `CACHE_TTL_SECS`）：期内直接用缓存、**不发起任何请求**；过期后带 `If-None-Match`/`If-Modified-Since` 条件请求，`304` 继续用缓存并续期，内容变了才重新下载。
- **离线回退**：网络错误或 5xx 时用缓存启动，底部帮助栏上方的状态行提示 `<warn> using the cached schema: …`（无缓存则照旧报错 exit 1）；404 等客户端错误仍按失败处理，不会被缓存掩盖。
- **同一次运行只抓一次**：表单模型与校验器共用同一份字节；本地路径/`file://` 不缓存。
- **SchemaStore 目录同一套机制**：目录文档（catalog.json）与 schema 共用上述缓存/TTL/离线回退；环境变量 `JSE_CATALOG_URL` 覆盖目录地址（测试或内网镜像用）。
- 想强制取最新：删除缓存目录（`rm -rf ~/.cache/jse`）或换一个 `JSE_CACHE_DIR`。

## 界面与键位

```
Server Configuration
$
  Name*                   webapp
  Mode                    http
> Server*                 port=8080 host=0.0.0.0 +1 --->
  Logging                 — --->
  Mounts                  1 item --->
  Auth                    — --->
  < Save and exit >       
  < Edit raw JSON >       
↑/↓ move · enter edit/open · esc back · ctrl+s/w save · / search · ? help
```

- 紧凑布局：标题行（当前菜单；schema 未给标题的菜单用文档键命名——map 成员键、数组条目 `key[N]`、oneOf 字段名——其**结构签名**（如 `{token*}`）改在底部元数据行以 `variant: …` 显示；锚点/引用对象的名字后跟 `: &name` / `: *name`）+ **面包屑行**（文档路径 `$.a.b[0]`：字段用 `.` 追加、数组下标用 `[N]`；oneOf 拣选器/变体编辑器等不扩展路径的层级不占段；引用菜单合并显示引用路径与锚点路径 `$.a.steps → $.b.steps`；过宽时保留尾部并加 `…`）+ 行列表 + **固定在终端最后一行的**操作提示栏（中性灰 `mHelp`，与紫灰色的描述行区分；只列常用键，完整键位见 `?`；内容不足时补空行）。**根屏状态行**渲染在底部帮助栏的正上方，光标行描述之下、瞬时操作提示（`Saved`、`undone` 等）之上；过长自动换行。状态行分两类：**信息类提示**（schema 来源 `schema from SchemaStore: …`、YAML 别名数量 `yaml: N alias(es) kept: …`）只在会话开始时显示，**首次按键后自动隐藏**；**警告类**（离线回退 `<warn> using the cached schema: …`、schema 编译失败等）整个会话保留。`esc` 返回的层级保留光标位置。
- `-s` 的值会**自动写入配置的 schema 指向**：JSON/JSONC 为顶层 `$schema` 字段（文件已有非空值则保留原值、空值/缺失则填入并置于首位）；YAML 不新增、也不填充 JSON 风格 `$schema` 键（文件里已有空值/显式 null 也保持原样），而是在文件头写 `# yaml-language-server: $schema=<位置>` 注释（已有非空 `$schema` 键或同类注释则保留）。保存后文件自带 schema 出处，下次可直接省略 `-s`（解析顺序见上）。schema 定义了 `$schema` 属性时（如 sing-box）该字段在编辑器中可见可改；YAML 注释同样会被识别为 schema 来源。
- 属性标记：红色 `*` = required（恒显，与该字段是否已填无关）。
- 变更标记：与**加载时/上次保存**的文档逐节点对比，值有变化的行在行尾显示粉色 `●`（对象/数组行在其子树含任何变更时也标记，父级逐层可见）；标题行右侧的 `●` 表示整个文档存在未保存变更；`ctrl+s`/`w` 保存成功后底部提示栏显示写入目标 `Write to <当前文件路径>`（不再只显示 `Saved`）、基线刷新、标记清除。`W`（大写）另存副本：菜单末尾出现 `> Write to           /origin/path/to/file.ext` 行（预填当前文件路径、可编辑），`enter` 把文档写入该路径（与 `ctrl+s` 相同的校验门，错误列表 `--force` 强制写入的也是该路径），成功提示 `Wrote to …`；`esc` 取消，路径为空时行内提示 `path required`。**路径自动补全**：输入行下方实时列出当前目录里匹配的条目（大小写不敏感；目录与其符号链接补 `/` 方便继续深入；点开头文件仅在前缀以 `.` 开头时出现），`tab`/`ctrl+n` 与 `shift+tab`/`ctrl+p` 前后循环补全，`enter` 始终按行内当前文本写入。`W` 只写副本——会话自身的保存目标、变更标记基线与未保存状态都不受影响。中止退出（ctrl+c）本身不写文件；若此前 `ctrl+s` 已保存过，磁盘保留该次保存，其后的修改丢弃。
- schema 未定义的键（文档里有、schema 里没有）：作为**警告**（非错误）对待，在所属菜单中显示为黄色行，带 `(not in schema)` 与值摘要，行尾 `<warn>` 也为黄色（校验错误改用红色 `<err>`）；`enter` 按当前值的类型编辑：字符串/数字就地输入（数字按 number 校验），布尔直接切换；没有值（缺失或显式 null）或值是对象/数组时用 `$EDITOR`（未设置时 `$VISUAL`，再退回 `vi`）打开只含该值的临时文件，JSON/JSONC 文件内容为 JSON、YAML 文件内容为 YAML，退出后解析并作为一步撤销写回（语法无效只提示并保留原值），`delete` 直接删除；对象菜单中 `a`/`A` 可新增这样的键值对，分别插在光标成员**前/后**（光标不在已有成员上时追加到末尾；输入键名 → `enter` → `$EDITOR` 打开空文件填值，退出后写入；文件留空则取消，无效 JSON/YAML 丢弃并提示；键名输入阶段 `esc` 取消）。这些键同时作为**编辑器级警告**进入问题列表（`unknown key … not in the schema`，黄色条目，与红色校验错误条目区分，enter 跳转定位到该行，删除即消）——JSON Schema 本身允许未知键，故不阻断保存，也不与 `additionalProperties: false` 的校验错误重复列出；顶层 `$schema`（编辑器自动写回的 schema 指针）不警告。**问题列表与行尾图标在每次文档修改后即时刷新**：加载时干净、编辑后才出现的问题（例如把字段指向内容不符合该字段约束的 alias）同样立刻在字段行显示 `<err>`/`<warn>`，根菜单问题计数行同步出现；计数行出现或消失时光标保持在原行。搜索与替换同样覆盖这些键（见下）。
- 值配色（按类型）：字符串绿、数字青、布尔洋红、枚举琥珀、对象/数组加粗；未设或显式 null 时预览的 schema 默认值改用比底部提示栏略亮的灰色（显式填写的值即使等于默认值也按类型着色），未设且无默认的 `—` 用暗灰；锚点/引用名 `&name` / `*name` 统一用紫色（值摘要列徽标与菜单标题后缀同色）；光标行整行反色高亮；`--->` 与 `●`/`[x]` 等标记用强调色。终端不支持颜色时自动降级为纯文本。
- **严重度图标**（Nerd Font / Font Awesome 私用区位码，需打补丁的终端字体，未安装时显示为空白方块）：**错误** = `U+F057`（fa-times-circle，红色 `mErr`），**警告** = `U+F071`（fa-exclamation-triangle，黄色 `mWarn`）。下文用 `<err>` / `<warn>` 指代这两个图标，出现位置：根菜单问题计数行、出错/警告字段行的行尾标记、问题列表与保存错误页标题、`current value not in options`、模型层降级提示（schema 深度超限、递归 `$ref`、ref 不可达）以及根屏状态行（底部帮助栏上方）的离线回退与 schema 编译失败提示。同一行同时有错误与警告时只显示 `<err>`（错误优先）。
- 每行 = 字段标题 + 右侧值摘要：左侧标题/键列按当前菜单最宽项在 16–42 格间自适应，值列在该范围内对齐；超过 42 格的标题/键完整显示（不省略），其值相应右移、不强制对齐；必填 `*` 保留；多行值（`run: |` 脚本块等）的换行与制表符折叠为空格，摘要始终单行；对象显示前 2 个成员 `k=v`（超出 `+N`；按 **schema 声明顺序**渲染，文档内键序不同也各行一致，schema 未定义的键殿后并保持文档顺序），数组 `N items`（**非纯对象列表**预览成员：`[4] a 1 {…} +1`——方括号为总数，列出前 3 个值（对象记 `{…}`、嵌套数组记 `[N]`），超出以 `+N` 收尾；纯对象数组保持 `N items`），oneOf 按**当前变体**给摘要——标量变体直接显示值（如 `tag` 的 string 变体显示 `geosite-github`）、枚举变体显示选项、数组变体同数组规则、布尔变体 `[y]`/`[n]`、对象变体有标题时保留 `变体标题 {…}` 以提供语境（无标题变体只显示 `{…}`，不合成 `variant N` 之类的无意义标签）；**嵌套 oneOf 组**（如 sing-box `DNSRule` 的匹配规则组与逻辑规则组）逐层取匹配到的叶子变体，按上述规则给出摘要；未设显示 `—`，无值时展示将生效的默认值。
- `↑`/`↓`/`j`/`k` 移动（到首行/末行后继续移动即**循环**；菜单列表、搜索、枚举选择器、问题/错误列表一致）；`gg`（第一个 `g` 只把组合键挂进命令缓冲区——右下角提示栏显示待命按键，**无超时**，直到下一个键完成 `gg`/`ga`/`gr`，或该键与组合无关时照常生效并清空缓冲；`esc`/`q` 例外——缓冲区有待消费字符时只清空缓冲，不执行返回/关闭/退出）或 `Home` 跳到**列表第一行**，`G` 或 `End` 跳到**列表最后一行**——主菜单列表与问题列表、保存错误列表、枚举选择器 overlay 一致支持；连选（`v`）开启时落在**第一个/最后一个可选行**（对象菜单的 key 行或数组菜单的条目行；跳过 `< Cmd >` 等操作行/状态行）并把途经的行全部并入选区；搜索框中 `G`/`g` 是查询文本、`Home`/`End` 是行内光标键，不参与跳转；`←`/`h`、`→`/`l` 与方向键同义（枚举行循环切换、容器行钻取、`←`/`h` 返回上级——根菜单没有上级，`h`/`←` 不退出、不弹保存询问，退出用 `esc`/`q`；输入框中 `h`/`l` 仍是普通字符）；`enter`/`→`/`l` 编辑字段或钻取子菜单（对象/数组/oneOf 行尾带 `--->`）；`esc`/`q` 取消编辑、关 overlay 或返回上级（`q` 与 `esc` 在菜单/overlay 中**完全同义**；任何输入框内 `q` 是普通字符，取消一律用 `esc`；`←`/`h` 仅菜单内同义，输入框内是普通字符）（光标位置记忆）；根屏 `esc`/`q`：有选中标记时先清空选区并留在编辑器，无选中时无未保存修改直接退出，有修改时弹 `Save changes? (y/n)`（`y`/`enter`/`space` 保存并退出，`n` 放弃修改退出，`esc` 取消并留下）；其余确认框（删除条目/替换变体等）`y`/`enter`/`space` = 是、`n`/`esc` = 否。`d`/`delete` 删除选中的键值对（可选与必填字段都移除该键——必填键删除后行保留为未设，保存期校验拦截缺失、重新填写即恢复，数组条目行同效；`<<` 合并来的 required 行仍拒绝——删除的是锚点映射中的字段，会让所有合并方失去该键，跳到锚点定义处可删）；对象菜单 `a`/`A` 新增 schema 未定义的键值对（见上）。`?` 打开/关闭键位帮助 overlay（esc/`?`/`q` 关闭，列表模式可用）；光标所在行的 schema `description`（含模型附加的提示，如嵌套数组按 JSON 编辑）以**紫灰色**（`mDesc`，与灰色帮助栏明确区分）显示在底部提示栏上方，按终端宽度自动换行（不省略；换行占用列表高度），无描述的行不占行。临时提示（`Saved`、`undone`、`empty fields hidden · z shows them` 等）同样固定在底部：顺序为描述行、提示行、帮助栏，菜单较短时用空行补齐，不会浮在列表中间。导航历史：`ctrl+o` / `ctrl+i`（即 `tab` 键）沿**导航轨迹**后退/前进——进入子菜单、返回上级、`gg`/`G`、`ga`/`gr`、搜索/问题/错误跳转都会记录离开的位置（每方向上限 100 条）；新的前进方向导航丢弃未走过的前进分支（浏览器语义），输入框内 `tab` 仍是补全、`ctrl+i` 不参与历史。
- 值导航：列表模式 `n`/`N`（或 `ctrl+j`/`ctrl+k`）跳到下一个/上一个**文档值非 null** 的条目（字段、容器、数组条目、schema 未定义键；跳过未设或显式 null、`< Add/Remove/Save >` 等操作行、oneOf 变体选择行与枚举 toggle 行；首尾循环）。全菜单都没有非 null 条目时光标不动。快速移动：列表模式 `f`/`F` 按下后等待输入一个字符，向下/向上把光标跳到下一个/上一个以该字符开头的 key（大小写敏感、首尾循环、跳过操作行与数组条目；等待输入时底部帮助栏提示 `Quick move: type a character to move down · esc cancels`）；`esc` 取消，输入其他键则取消快速移动并照常处理该键。
- 复制：列表模式 `y` 复制当前条目的 **`"key": value` 键值对**，`Y` 复制**值**本身；文本格式随打开的文件类型——JSON 文档得到 `"name": "webapp"` 与紧凑 JSON（保持键序与 `1.0` 这类数字字面量），YAML 文档得到 `name: webapp` 与 YAML 文本（容器值/容器对为多行块，锚点/引用以普通值导出）。字符串两种格式都按原样复制（不带引号/转义），数字/布尔/显式 null 按字面量。数组条目行没有对象键：**数组条目菜单里 `y`/`Y` 都复制元素值、`x`/`X` 都剪切元素值并删除条目**（其他页面 `y`/`x` 仍拒绝无对象键的行并提示 `y copies object keys only`），`Y`/`X` 在任意行都复制/剪切**值**；文档中缺失的字段提示 `no value to copy`，操作行提示 `nothing to copy`。成功提示 `Copied key-value pair` / `Copied value`，失败提示 `copy failed: …`，提示中不会显示被复制的内容。剪切：列表模式 `x` 剪切当前条目的键值对（等价 `y` + 删除）、`X` 剪切值（等价 `Y` + 删除）；多选/连选选中时整批剪切（对象菜单 `x` 先复制为一个对象/映射再整批删除，`X` 复制换行连接的各值；数组菜单 `x`/`X` 都复制换行连接的各条目值再整批删除）；剪贴板写入失败时不删除；删除侧的拒绝规则（required 合并行、锚点载体等）与 `d` 相同，拒绝时行保留、剪贴板中已复制的内容保留、提示拒绝原因；剪切 = 一步撤销。系统剪切板写入依赖平台工具：Linux Wayland `wl-copy`、X11 `xclip`/`xsel`，macOS `pbcopy`，Windows `clip`；工具不可用时复制失败并在底部提示。
- 多选：列表模式 `m` 在光标行上开/关选中标记（选中的行行首显示红色 `>`、key（数组菜单为 `key[N]` 标签）变红；可选行为对象菜单的键值行（字段/容器行与 schema 未定义键）与数组菜单的条目行，操作行不可选；选区随菜单状态保留，返回后恢复）。选中后 `y` 一次复制全部选中项——对象菜单复制键值对（JSON 文档为紧凑 `{…}` 对象、YAML 文档为块映射，可直接用 `p` 智能粘贴到别处；无值的选中行跳过），数组菜单按行序复制各条目值（换行连接，同 `X`）；`d` 一次删除全部选中项（整个按键 = 一步撤销；数组条目按下标倒序删除，`<<` 合并来的 required 行跳过并提示）；`x`/`X` 批量剪切同样生效；操作后选区清空。无选区时 `y`/`d` 照常只作用于光标行。连续多选：`v` 开/关可视化连选——选区为**起点（按 `v` 处）与光标之间的连续范围**，`j`/`k`（或方向键）移动时自动扩大/缩小（范围内的操作行跳过），`gg`/`G`（及 `Home`/`End`）一步跳到**第一个/最后一个可选行**（对象菜单的 key 行或数组菜单的条目标签 `key[N]`；跳过 `< Cmd >` 等操作行/状态行）并把途经的 key 全部标记——跳转只扩大选区、不缩小，再按 `v` 或 `esc`/`q` 结束（`esc`/`q` 只退出连选，不退出菜单）；选中行以 `>` 标记：非光标的选中行**始终为亮红色**；光标位于选中行上时 key 加粗并保持亮红色，其 `>` 连选开启时为亮红色、关闭后恢复光标本来的白色；进入/返回子菜单即结束连选，批量 `y`/`d` 后选区清空但连选开关保持。特殊模式的操作提示统一显示在底部帮助栏（替换标准键位提示）：连选开启时为 `Visual select: j/k, gg/G or arrows mark rows · y copy · d delete · v/esc stop`，存在选中行时为 `Marked N rows: y copy · d delete · m unmark`，快速移动等待输入时为 `Quick move: type a character to move down · esc cancels`。
- 智能粘贴：列表模式 `p`/`P` 读取系统剪切板并合并进映射/数组——`p` 贴进**当前面包屑路径**的映射/数组（当前菜单展示的容器），`P` 贴进**光标所指**的映射/数组（光标不在映射/数组行上时同样落到当前菜单的映射/数组）；`P` 在键值行上遇到剪切板里的**单个值**（`123`、`"hello"`、`true`/`null`，YAML 文档还接受 `hello` 这类裸标量）时直接**替换该行的值**（一步撤销）——多选时替换**全部选中行**的值（无值的选中行创建该键，提示 `pasted value into N keys`）；`p` 遇到单个值只提示、不动文档：完整 JSON 对象 `{…}` 的键合并进映射（已有键原位覆盖值，新键按剪切板顺序插到光标行**下方**（`p`）或**上方**（`P`——这是把键插到游标前面的方式；光标行未设键时追加到末尾））；**数组条目菜单里 `p`/`P` 是位置粘贴**——剪切板内容（部分元素、完整 `[…]` 数组，或完整 `{…}` 映射——后者作为**单个条目**插入）`p` 插到光标条目**下方**、`P` 插到**上方**（光标不在条目行上时都追加到末尾）；不带花括号/方括号的部分内容按「键值对 / 数组元素」自动识别（单个结尾逗号自动剥除；完整 `{…}`/`[…]` 闭括号前的单个结尾逗号同样容忍）；键值对贴进枚举数组、数组元素贴进映射、剪切板为空或不是合法 JSON 时只提示、不动文档；每次粘贴 = 一步撤销，保存时照常校验。编辑 YAML 文档时同样接受 YAML 形式的内容：块映射（逐行 `x: 1`）、块序列（逐行 `- 1`）与流式 `{…}`/`[…]` 都能自动识别（JSON 是 YAML 子集，JSON 文本照常可贴），剪切板中的锚点/别名粘贴为普通值（不保留引用）；JSON 文档仍只接受 JSON。不支持 JSONC 注释。
- 空字段过滤：列表模式 `z` 切换隐藏/显示**文档中没有值的对象键**（缺失或显式 null 的 schema 字段、`additionalProperties`/map 成员、schema 未定义键；默认值不算文档值，仅靠默认值显示的行同样隐藏）。有值的键、空容器 `{}`/`[]`、null 数组条目（按索引而非键）不隐藏。过滤开启时**菜单列表正下方**显示一行灰色 `[empty hidden]`（位于描述行与提示行之上，窄终端也不受影响），切换瞬间另提示 `empty fields hidden · z shows them`；再按 `z` 恢复。隐藏期间从搜索或问题列表跳转到被隐藏的键会自动关闭过滤并提示 `empty fields shown`，保证跳转落点可见；该状态只影响列表显示，不改文档、不进撤销栈。
- `space` 切换布尔（`[y]`/`[n]`）与枚举数组成员（`[x]`）；枚举行 `←`/`→` 直接循环切换；标量字段 `enter` 就地输入（非法值红字拦截）；`json` 字段仍在内置 textarea 编辑（`ctrl+s` 应用）；根 `< Edit raw JSON >`（YAML 文件显示 `< Edit raw YAML >`）挂起 TUI，用 `$EDITOR`（未设置时 `$VISUAL`，再退回 `vi`）打开整份文档的临时文件，内容为文件格式（JSON 或 YAML），退出后解析并作为一步撤销应用；schema 未定义键的标量值就地编辑，无值或对象/数组值用 `$EDITOR`，临时文件只含该值（见上）；**含换行的字符串**（脚本块、内嵌文档等）`enter` 不再就地输入，直接进 `$EDITOR`（临时文件只含该值，JSON 转义或 YAML 块标量）；列表模式 `e` 主动用 `$EDITOR` 编辑光标行的 value（字段行、schema 未定义行、对象/数组容器行；无值的操作行提示 `no value to edit`），`E` 物化别名引用（原 `e` 的展开功能）；编辑器报错或语法无效只提示并保留原文档（GUI 编辑器需等待模式，如 `code --wait`）。
- 文本输入自动补全：候选 = 文档中**同键**已存在的值（去重、按文档顺序、不含本处；字符串字段取字符串值，`integer`/`number` 字段取数字字面量），按已输入前缀过滤（大小写不敏感）。**多行值（脚本块、内嵌文档等含换行或制表符的字符串）不作为候选**——既无法补全单行字段，也会撑破提示行。**schema 给出可选值时优先只用这些值**（`oneOf`/`anyOf` 里「开放字符串 + 闭合字符串集合」展开成的候选，如 workflow `shell` 的 `bash`/`pwsh`/`python`/…）：只要已输入文本仍匹配其中某个选项，候选就只列选项（混不进文档值）；直到前缀与**全部**选项都不匹配，才回退到上面的文档候选。字段始终是自由文本，schema 未列出的值照常可输入（保存期校验兜底）。带 `x-tag-reference` 的字符串字段（如 sing-box 的 `http_client`/`detour` 引用）改为按**引用域取 `tag` 值**（`http_client` → `http_clients[].tag`，兼容单复数两种键名，不限层级；复合域名还接受末词（含复数）在首词同名成员下的嵌套匹配，如 `dns_server` → `dns.servers[].tag`）作为候选；`oneOf`/`anyOf` 的标量变体与对象变体内的字符串同样按上述规则补全（变体沿用引用字段自身的键，`$ref` 共享的定义也如此）。灰色提示行 `tab: a · b · c` 显示三个候选的**滚动窗口**（随 `tab` 选择前移，两侧 `…` 表示窗口外还有候选），`tab`/`ctrl+n` 正向、`shift+tab`/`ctrl+p` 反向循环填入（两端回绕；从空选择开始反向时落在最后一个候选；`ctrl+n`/`ctrl+p` 兼容不发送 `ESC[Z` 的终端），`enter` 提交。无候选或无匹配时不显示提示行。
- YAML 锚点/别名：别名引用（如 `copy: *base`）**不展开成副本**。进入别名对象的菜单时，顶部出现 `< Expand >` 行（快捷键 `E`，光标停在引用行上时 `E` 直接物化该行），其下展示的是**被引用的原始对象**（`&base` 定义处）的字段——查看与编辑都直接作用于该原始对象，所有引用同步变化（YAML 引用语义）。引用行与锚点定义行的值摘要列分别带 `*base` / `&base` 徽标（与值对齐）；进入锚点/引用对象的菜单时，标题行追加 `: &base` / `: *base`，引用菜单的面包屑合并显示两个路径（`$.jobs.build_apple_app_store.steps → $.jobs.build_apple.steps`）。`ga` 从引用行跳到锚点定义处，`gr` 跳到该锚点的其他使用处——其余 `*alias` 引用与 `<<` 合并了它的映射（多个时打开选择器，`esc` 返回）。选择 `< Expand >` 把引用**物化为独立副本**（锚点身份丢弃，提示 `alias expanded`），此后的编辑只影响副本；未展开时保存原样写回 `*base`，锚点 `&base` 亦原样保留。`&` 在光标字段上**添加/修改锚点**（输入框出现在光标行下方，预填当前名称，改为空删除锚点——被引用时拒绝并提示引用数；改名自动同步所有引用，重名拒绝）；`*` 在光标字段上**添加/修改引用**（同样在光标行下方，`tab` 在现有锚点名间补全：候选项按**字段 schema 的类型**过滤——对象/数组/布尔/枚举/字符串与数值只列出能合法填入该字段的锚点，并跳过会造成循环引用的锚点；提示行与补全顺序**随输入前缀实时更新**，前缀匹配大小写不敏感，填入的名称保持原大小写；改为空删除引用，值随之清空——required 字段拒绝）。引用目标若包含该字段本身则拒绝（防循环引用）。**展开本身是一步可撤销的文档修改**（锚点身份属于文档内容），`u` 一步恢复引用；展开后文档标记为已修改，退出时会询问保存。标量/枚举/布尔别名没有子菜单，行上就地编辑同样写入被引用的原值。
- YAML 合并键（merge keys）：`<<: *base1` / `<<: [*base1, *base2]` 原样保留，映射菜单按 YAML 语义**合并展示**，并保持 **schema 声明顺序**：merged keys 落在对应字段的 schema 槽位上（与普通字段一样参与排序；同一 `<<` 内按 anchor 顺序、再按 anchor 对象的键序），schema 未定义的 merged keys 排在本映射自有行之后（按合并顺序）；本映射已定义的键、靠前 anchor 已提供的键按优先级遮蔽，不重复显示。**合并链逐层按同一规则解析**：anchor 自有的键优先于它自己通过 `<<` 继承来的键（即使 `<<` 写在自有键之前），继承来的键沿链取到实际定义它的映射——值摘要徽标、面包屑与编辑都指向该来源映射（与 `yaml.v3` 的解析结果一致）。合并出的键参与 oneOf 变体识别与 required 标记：菜单按实际匹配到的变体显示，缺失的 required 键由保存期校验拦截（`--force` 除外）。值摘要前带来源 `*base1` 徽标，标题行追加 `<<: *base1 *base2`。**修改 merged key 直接作用于 anchor 映射中的字段**（与 alias reference 一致）：就地输入、`space`、枚举循环、`e`、`&`/`*`、钻取子菜单以及 `d` 删除都写入定义该键的源映射，所有合并该 anchor 的映射同步变化（required 键的 `d` 仍拒绝——删除会让所有合并方失去该键）。需要单独修改某个映射时按 `E` 在当前映射中显式展开该值（物化为独立副本并遮蔽合并值，提示 `merged key expanded`），此后编辑只影响本映射；删除这种**已展开**的自有副本时，即使 schema 标记 required 也允许——合并值重新接管，不会造成缺字段。merged key 上 `ga` 直接跳到来源映射中**定义该键的字段行**（光标落在该字段本身，容器字段也不进入其子菜单；`esc` 返回），`gr` 跳到该 anchor 的**其他使用处**——直接 `*alias` 引用与其他 `<<` 合并了它的映射（多个时打开选择器，`esc` 返回）。光标停在 merged key 上时面包屑在路径后以箭头标注来源路径（`$.jobs.build2 → $.jobs.build_base1`），移到非合并键上箭头与其后路径清除，移到来自不同 anchor 的键上自动更新。映射编辑界面按 `<` 打开 **Merge Keys** 输入（**标题与面包屑下方**，作用于整个映射而非光标行）：预填当前合并的 anchor 名；支持**多个 anchor**，空格或逗号分隔，也可带 `*` 前缀（`base1 base2`、`*base1, *base2` 均可），`tab` 补全正在输入的词并自动跳过已列出的锚点、补全后留出分隔符便于连续输入（候选项只含**映射类型且不会形成循环**的锚点；按输入前缀实时过滤，大小写不敏感）；`enter` 应用为新合并列表（键值随即自动补充），改为空并 `enter` 清除全部合并。目标映射尚未创建（无值或显式 null，例如 `a` 新建后尚未填值）时自动创建为空对象再合并；未知锚点、非映射锚点、合并自身/经合并链回到本映射（循环）均拒绝并提示。`u` 撤销/重做覆盖合并列表变更；被合并引用的锚点在解除合并前不能删除或去锚（`d`/`&` 拒绝并提示），保存时写回器仍会校验别名先于定义（合并引用了已删除/被移动的锚点时报错拒写，防止生成无法加载的文件）。
- 数组菜单：`< Add item >` 追加（对象条目进入条目表单，顶部 `< Remove this item >` 需确认 `Remove this item? (y/n)`）；`数字gg` 跳到下标为该数字的条目（多段数字累积、越界钳到最后一条、`0gg` 即第一条；仅数组条目菜单，其他菜单数字无效果、`gg` 仍跳第一行）；`a` 在光标条目**前**插入新条目、`A` 在其后（光标不在条目行时按列表位置取最前/追加；标量条目插入 null 占位，取消编辑留下空位可 `d` 删除；对象/数组条目立即落空容器占位）；条目行 `d` 直接删除（无确认，摘要即时可见）；条目行 `J`/`K` 将光标条目下移/上移（光标跟随移动，一次按键一步撤销；已在最上/最下或单条目列表时提示、文档不变）；`--accessible` 的条目管理菜单提供 `Move item up…`/`Move item down…`（挑选条目后移动）；`items` 为枚举的数组显示为多选 toggle 列表。
- oneOf 菜单：每变体一行（`●` 当前 + 变体签名；无标题变体不显示回退标签，仅有标记与签名）；**无值时**先选类型再编辑；**已有值时 enter 跳过类型拣选，直入当前变体的编辑界面**（拣选器打开时光标即落在 `●` 行），编辑界面内 `ctrl+t` 随时呼出类型拣选器切换变体（切换已有值仍先确认 `Replace current value? (y/n)`）。**标量变体**（如 `string`）：选中后**退回上一级菜单**，在字段行上就地编辑（输入框与补全提示都在该行，与其他字段一致），提交后 `●` 移至该变体；枚举变体进选项 overlay（保持在拣选器内），对象/数组/**映射**（`additionalProperties`，如 workflow `env`/`matrix`/`step.with`）变体进入各自的子菜单（映射变体列出文档键，`a` 新增、`d` 删除，值按子 schema 编辑）。数组 `items` 为全对象 oneOf 时不选变体：`< Add item >` 直接进并集字段菜单，按已填字段（如判别 const）自动识别并收窄到对应变体，改判别键即可切换（菜单翻转后光标仍停在原字段行，例如 `type*`）；**经 `<<` 合并来的键同样计入识别**，因此合并出的判别键（如 workflow job 的 `runs-on`/`uses`）能把菜单收窄到正确变体，不会残留另一变体的 required 标记。
- `/` 搜索**从当前面包屑路径向下**（子树范围，逐次打开重建索引）：查询**默认按 Go RE2 正则匹配**（`alt+x` 切到字面量子串匹配，见下）：匹配标题/键名**或该行自身的值**（大小写不敏感，`alt+i` 随时切换大小写敏感并实时重筛，叶子行匹配其值、未设字段匹配将生效的默认值；对象/数组/oneOf 行的概览是子项汇总，**不参与匹配**——子项自身行会命中，避免同一个值既列父行又列子行，未设 `—` 不参与）；结果每行 `面包屑路径  概览`（路径格式与面包屑一致如 `$.server.port`、`$.mounts[0].src`，概览同主菜单值列，oneOf 变体行显示结构签名如 `{token*}`（仅在该字段**无值**时出现；有值时字段行已带值，不再重复 `string`/`list of string` 之类的类型行）、不出现无意义的 `variant N` 回退标题，数组按文档实际条目逐条索引，schema 未定义的键连同其嵌套值一并索引），enter 跳转到对应菜单并定位该行——**跳转可逆**：落点菜单按 `esc` 回到搜索结果（索引与结果按当前文档重建、查询与光标保留；落点若继续下钻，`esc` 先逐级返回，回到落点层再回列表，与问题列表跳转一致），在搜索列表按 `esc` 关闭并回到**打开搜索前**的菜单（跳转不会变成常驻位置；要在落点留下继续工作，就在那里再按 `/` 或 `r`，即在该处重新起一次搜索）；结果列表用 `↑`/`↓` 或 `ctrl+j`/`ctrl+k` 移动（首尾循环）；overlay 底部有键位帮助行。结果排序——键名与查询完全一致（大小写按开关）的行置顶，其余保持文档顺序；以 `$` 开头的查询（`$`、`$.`、`$[`）按**路径**检索（如 `$.server.port`、`$.mounts[0].src`），从文档根锚定（前缀语义，允许最后一段未输完；字面量模式直接前缀匹配，正则模式在去掉 `$` 的路径体上匹配且 `[N]` 下标括号自动转义，故粘贴面包屑路径即可命中）；以 `.` 开头的查询同样按**路径**检索，但关键字从**任意层级**的路径段起匹配（如 `.build_app` 命中 `$.jobs.build_apple_app_store` 及其子树，节点本身排在子节点之前；点分段须落在连续的路径段上；各段先按段前缀、再按段内包含、最后按模糊子序列匹配——记不全的键名也能命中，精确的命中排在前；`.` 查询在正则模式下也按此字面量分段规则匹配，正则语法只作用于兜底的文本匹配）。两类路径查询都先列路径命中，其后把**值中包含该查询文本（含 `$`/`.` 前缀）的行**作为兜底补充（按未截断的原始字符串值匹配，正则/字面量模式一致；路径已命中的行不重复列出）。不以 `$`/`.` 开头的查询一律按文本匹配，因此含点/斜杠的值（如 `0.0.0.0`、`/mnt`）仍可直接搜。`alt+x` 在**正则模式**（默认开启）与字面量模式间切换（overlay 底栏显示当前模式 `alt+x regex`/`alt+x literal`，每次打开重置为正则）：正则模式用 Go RE2（`regexp`，无新依赖）编译查询，匹配目标与字面量模式完全一致（以 `$`/`.` 开头的查询仍按路径匹配并锚定；否则匹配标题/键名/该行自身的值；替换模式匹配的是字符串值，查询原样编译，不做锚定剥离）；大小写开关在正则模式改为给模式加 `(?i)` 前缀（正则始终匹配原始大小写文本，`\p{Lu}` 之类照常可用），完全匹配叶子键名（路径模式下整条路径）的行仍置顶。无法编译的正则显示 **0 结果**并在底部红字提示 `invalid regex: … · esc close`，绝不退回字面量匹配。
- **搜索替换（字符串值）**：列表模式 `r` 直接进入，或 `/` 打开后按 `tab` 挂出第二行替换输入框（`tab` 在搜索/替换框间切换焦点，esc 关闭）。替换模式的结果列表改为**字符串值**命中预览 `路径  旧值 → 新值`（数字/布尔/枚举/容器概览不参与，仅文档中实际存在的字符串——未设字段不替换默认值，schema 未定义键里的字符串同样可替换），范围与 `/` 相同。替换框内 `enter` 只替换当前高亮值（该值内所有出现处）并移到下一命中；搜索框内 `enter` 跳转同样可逆（`esc` 回到替换列表，再 `esc` 回到打开搜索前的菜单）；`ctrl+r` 一次替换全部，overlay 关闭并提示 `replaced N occurrence(s) in M value(s)`。空查询 enter/`ctrl+r` 均不动作；大小写开关对搜索与替换统一生效；`alt+x` 正则模式（默认开启）对搜索与替换同样生效，替换串可用 `$1`/`${1}` 引用捕获组（`$0` 为整段匹配），`ctrl+r` 的计数为各值内匹配次数之和。
- 宏录制/播放：`@` 开始录制（底栏右侧红色 `● REC n` 计数），再按 `@` 停止；`.` 回放最后一次宏。输入框（就地编辑/raw 编辑/搜索）内 `@`/`.` 是普通字符、会被录下并在回放时照常键入；录制中 `@` 在任何非输入上下文（含 overlay）优先停止录制，非录制时 `@`/`.` 在所有非输入上下文（含 overlay，如问题列表）一律拦截——overlay 内也能起录/回放（问题列表改用 `esc`/`q` 关闭，宏内用 `esc` 关列表）。空缓冲停止 = 取消并保留上一条宏；录制中（非输入上下文）`.` 被忽略且不记录，回放不会嵌套触发；`q` 在非输入上下文与 `esc` 完全同义（见上），被录成 `esc`，输入框内则是普通字符、照常录制；**仅内存、单条宏**、上限 500 键（达到即停止并保留已录部分）。回放从当前界面状态立即重放，遇到中止（ctrl+c）或 `Save and exit` 即停止（提示停在第几键），`ctrl+s` 只保存、回放继续，落到不同菜单可能产生不同结果，由使用者负责。
- 撤销/重做：列表模式 `u` 撤销 / `ctrl+r` 重做；每次按键 = 一步（替换全部也是一步）；新修改清空重做链；上限 100 步；撤销/重做不改变上次保存基线（变更标记仍相对上次保存）；撤销后若当前菜单路径已不存在则退到最近仍存在的层级；输入框（就地编辑/raw 编辑/搜索）内 `u` 为普通字符，搜索替换 overlay 内 `ctrl+r` 仍为全部替换；宏录制照常记录/回放这两个键。

列表模式 `ctrl+s` 或 `w` 保存并**停留在编辑器**（成功提示 `Saved`，变更标记清零，可继续编辑后再存；输入框内 `w` 仍是普通字符）；根菜单 `Save and exit` 保存并退出。根菜单 `esc`/`q`：存在选中标记时先清空选区并留在编辑器（提示 `selection cleared`）；无选中时：无未保存修改则直接退出（exit 0，`No changes, nothing written`，不写文件）；有修改时询问 `Save changes? (y/n)`——`y`/`enter`/`space` 保存并退出（校验失败仍走错误页，`--force` 下可强存），`n` 放弃修改退出（exit 130），`esc` 取消询问并留在编辑器。校验错误全屏列出（`--force` 下 `y` 强存）。`ctrl+c` 任何时候退出（exit 130；此前 `ctrl+s`/`w` 已写盘的保留）。

## 保存与退出码

| 退出码 | 含义 | 结果行（stdout） |
|---|---|---|
| 0 | 已保存，或无未保存修改时退出 | `Saved to <path>` / `No changes, nothing written` |
| 1 | 运行错误（加载/解析失败等） | — |
| 2 | 用法错误（无 schema 来源、无输出路径） | — |
| 130 | 用户中止（`n` 放弃修改 / ctrl+c；此前未保存过 / 已 `ctrl+s`/`w` 保存过） | `Aborted, no changes written` / `Saved to <path>; aborted (changes after the last save are lost)` |

- 保存前用 schema 库做权威校验；有错误则列出并返回编辑，`--force` 可强存（结果行 `Saved with validation errors (--force): <path>`）。
- 写入为原子写（同目录临时文件 + rename），保留已存在文件的权限位；键序与数值字面量（如 `1.0`）原样保留；schema 之外的未知键、`$schema` 键均保留。输出格式由扩展名决定（见「配置格式」）；raw 编辑与 `$EDITOR` 外部编辑的修改同样按原格式写回。
- `--accessible`：行式问答模式（无全屏 TUI，适合管道/屏幕阅读器）。注意：管道喂答案时脚本必须覆盖全部提问——required 输入框不能靠空行取默认值；stdin 读尽后会话中止。

## 支持的表单关键字子集

| 类别 | 关键字 | 表单行为 |
|---|---|---|
| 元信息 | `title` `description` `default` `examples[0]` | 标题/描述/预填/占位符 |
| 标量 | `type: string\|integer\|number\|boolean` | 文本输入 / 确认框 |
| 枚举 | `enum` / `const` | ≤5 选项行内单选，否则下拉 |
| 数值约束 | `minimum` `maximum` `exclusiveMinimum` `exclusiveMaximum` `multipleOf` | 输入校验 |
| 字符串约束 | `minLength` `maxLength` `pattern` | 输入校验 |
| 对象 | `properties` `required` | 字段按 schema 顺序；required 空值拦截 |
| 对象映射 | `additionalProperties` | 键为文档成员（`a` 添加、`d` 删除），值按子 schema 编辑（如 sing-box HTTPHeader：字符串或字符串数组） |
| 模式映射 | `patternProperties`（单个模式 + `additionalProperties: false`） | 同上，但 `a` 新增的键必须匹配该 Go 正则（不匹配时行内提示 `key must match <pattern>`；如 GitHub workflow 的 `jobs`）。多个模式、schema 形式或缺失的 `additionalProperties`、无法用 Go RE2 编译的模式仍按未声明处理 |
| 数组 | `items` `minItems` `maxItems` | items.enum→多选；标量条目→逐条输入；对象条目→逐条表单 |
| 组合 | `oneOf` `anyOf` | 变体选择后进入子编辑器；全 const/单值 enum 变体合并为一个枚举选择；**开放字符串 + 字符串枚举**（如 workflow `shell`）合并为单个文本输入，枚举值作为 `tab` 补全候选（前缀匹配任一选项时只用这些候选，全不匹配才回退到文档候选；自由文本仍可输入） |
| 组合 | `allOf` | 浅合并（properties 拼接、required 并集、约束取更严者）；其中的 `oneOf`/`anyOf` 按分配律展开为嵌套变体（sing-box rule = 匹配字段 allOf action） |
| 引用 | `$ref` | 本地指针与远端 ref 均支持（缓存 + 环保护，深度上限 32） |

## 降级规则

- 未列出的关键字不参与表单生成，但**保存时仍由 jsonschema 库权威校验**。
- 无法表单化的属性（不可达 `$ref`、数组套数组、未知类型）渲染为「Edit as JSON/YAML」文本域（YAML 文件用 YAML 语法）：提交时做对应格式的语法校验，语义合法性交给保存期校验。
- schema 编译失败（非法 schema / 远端 ref 不可达）→ 保存期校验自动停用，根屏状态行（底部帮助栏上方）提示 `<warn> schema compile failed, save-time validation disabled`。
- 加载的配置若已有校验问题，不阻止编辑：根菜单首行显示问题计数 `enter` 打开问题列表，`↑/↓`（或 `ctrl+j`/`ctrl+k`）选择、`enter` 跳转到对应字段修改、`esc` 关闭；计数格式为 `<err> N validation error(s)`、混合时 `<err> N validation error(s) · <warn> M warning(s)`、仅警告时 `<warn> M warning(s)`；**问题列表实时刷新**——字段修好后计数、`<err>`/`<warn>` 行标记与该条目即刻更新/消失（全部修完状态行自动隐藏，保存期校验仍是最终兜底）；**从问题列表跳转后，在落点菜单按 `esc` 会回到刷新过的问题列表**（光标位置保留），再 `esc` 关闭列表；若在落点继续下钻，`esc` 先逐级返回，回到落点层后再返回列表（`/` 搜索跳转或重新打开列表会清除该返回点）。出错字段行尾标 `<err>` 红色（其父级对象/数组行同样标记）；仅未知键警告的字段标黄色 `<warn>`；问题列表条目同样按严重度着色（错误红、警告黄）；条目内的位置与面包屑同风格（如 `at '$.server.port':`、`at '$.items[0].tag':`）。保存失败的错误列表同样支持 `enter` 跳转。
- 明确不做：`format` 校验、数组条目重排序 UI、`if-then-else`/`not` 的表单化、多模式 `patternProperties`、配置路径远端 URL。

## 开发

```sh
cargo test                                        # 单测 + e2e（accessible 行协议 + pty 冒烟）
cargo run -- -s examples/server.schema.json examples/server.config.json
cargo build --release --target x86_64-unknown-linux-musl   # 静态发布构建
```

代码结构（`src/`）：`doc/jsondoc`（arena 保序 JSON 文档）、`doc/mod`（按扩展名分派格式的 `Codec` 注册表）、`doc/jsoncdoc`（JSONC 注释解析与写回）、`doc/yamldoc`（YAML 注释/别名/merge 事件解析与自研 emitter）、`fetch`（本地/远端统一加载与磁盘缓存）、`catalog`（SchemaStore 目录加载与 fileMatch 匹配）、`smodel`（schema→表单模型）、`validate`（保存期校验）、`ui`（menuconfig 菜单、schema 检索选择器与 `--accessible` 行协议）、`main`（CLI）。

测试布局：`src/**` 内联单测（各模块 1:1 移植自 Go 测试）+ `tests/e2e.rs`、`tests/schemastore.rs` 黑盒 e2e（stdin 脚本 + portable-pty 终端驱动）。

发布由 `.github/workflows/release.yml` 完成：推送 `v*` 标签即构建 Linux（musl 静态）/ macOS / Windows 的 amd64 与 arm64 版本（版本号/提交/构建时间经 `JSE_VERSION_OVERRIDE`/`JSE_COMMIT`/`JSE_BUILD_DATE` 注入 `build.rs`），生成带校验和的压缩包并创建 GitHub Release。

```sh
git tag -a vX.Y.Z -m "jse vX.Y.Z"
git push origin vX.Y.Z
```
